# P4.3 — Repair telemetry

Product run reports expose repair cost and outcome separately from the primary bounded-model token totals.

The report fields are:

- `repairAttemptCount`
- `repairInputTokens`
- `repairOutputTokens`
- `repairDurationMs`
- `repairChangedFiles`
- `repairOutcome`

## Semantics

These fields describe repair work only; they are not folded into the existing primary `tokens` object. This keeps it possible to compare the bounded-path savings against repair overhead without double counting.

For newly produced artifacts, a run that definitively performed no repair should record explicit zero/empty values as appropriate. For older artifacts that predate P4.3 and contain no repair telemetry, the report returns `null` rather than inventing zero-cost repair data.

`repairChangedFiles` is normalized to a unique, deterministic repository-relative file list when the report is built.

The report reader accepts the six canonical flat fields from `run.json`, `telemetry.json`, or `receipt.json`. It also accepts the equivalent fields under a `repair` object (`attemptCount`, `inputTokens`, `outputTokens`, `durationMs`, `changedFiles`, `outcome`) to keep the report compatible with structured telemetry producers.
